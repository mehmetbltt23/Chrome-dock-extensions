# Security model

DockTabs has no server component and performs no network requests of its own. Shortcut URLs leave local storage only when Chrome navigates to a URL selected by the user.

The extension requests `tabs`, `storage`, `favicon`, `scripting`, and `search`. It has no side-panel or required host permission. Chrome blocks content scripts on its new tab page, so DockTabs overrides that page with a packaged page that loads the same Web Dock script and a search box. `search` lets that box hand plain text to the user's default search engine through `chrome.search.query`; DockTabs never sees or stores results, and Chrome shows no install warning for it. Address-like input is validated as `http/https` before navigation. The scripting capability only registers the packaged Web Dock after the user explicitly grants the optional `http://*/*` and `https://*/*` origins from Settings. Disabling the feature unregisters the script and removes those origins. The dock does not read page content; it renders from local DockTabs state inside an isolated Shadow DOM. Chrome's virtual favicon resource is read only inside the privileged extension service worker, converted to a bounded image data URL, and persisted with the local shortcut so the icon survives worker and browser restarts. No packaged extension resource is declared web-accessible. DockTabs cannot inspect cookies, history, request bodies, passwords, or tokens. The Manifest V3 service worker is event-driven and contains no polling timer.

Imported JSON is checked against the versioned runtime schema. Vivaldi HTML is parsed with `DOMParser`; only text and validated `http/https` URLs are extracted. No imported markup is inserted into the interface. Files larger than 5 MB are rejected. Extension pages use a self-only CSP and the build validator rejects dynamic `eval` or `Function` construction in the service worker.

The `tabs` permission is sensitive because Chrome exposes tab titles and URLs. DockTabs uses them only in memory to match and activate shortcuts. Persisted data remains in `chrome.storage.local` until the user exports, removes, or resets it.
